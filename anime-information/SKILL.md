# Anime Information

专为整理本地动漫文件而生的 Agent Skill。核心工作是理解文件和目录、运用动漫领域规则并给出可审核的整理方案；辅助脚本只做只读扫描，不替 Agent 作最终判断或执行整理。

## 工作流程

按顺序完成以下步骤。任何一步出现关键歧义、权限问题或目标冲突，都先停下相关操作并报告，不要用猜测补齐信息。

### 1. Scan：确认范围并扫描

- 确认用户指定的根目录；相对路径先解析为明确路径。只扫描该目录，不扩大到整个磁盘、家目录或相邻挂载点。
- 先读取用户已有的目录和命名习惯；若目标目录中已有稳定结构，默认保留。
- 可运行 `python3 <skill目录>/scripts/inspect_anime.py <目标目录>` 获取 JSON 清单。脚本只读；也可用 `find`、`file` 等系统工具补充。保留原始相对路径和目录层级。
- 按 `references/naming.md`、`episodes.md`、`subtitles.md`、`extras.md` 的规则识别视频、字幕、字体、图片/扫图、音频/OST、压缩包、光盘镜像、PV、特典和字幕组附带文件。扩展名只是线索；对可疑内容用 `file` 或其他只读工具核验。
- 不要忽略隐藏项、符号链接、损坏文件、未知扩展名或特殊文件（如 FIFO/socket）；标记出来。扫描符号链接时不沿链接扩展到目标树。

### 2. Inspect：检查媒体属性

- 对需要区分版本、验证字幕或判断重复的媒体，按需使用 `ffprobe` 或 `mediainfo`，记录容器、时长、视频/音频/字幕轨、编码、分辨率、位深、HDR、章节和附件等相关信息。
- 对普通文件记录扫描器提供的 `device` / `inode` / `nlink`。同设备且 inode 相同表示多个路径是同一文件的硬链接，不是多份内容；`nlink` 可能包含扫描范围外的链接。
- 只在确有帮助时计算 Hash；相同 Hash 才是内容相同的强证据。文件大小、名称、时长相同都不能单独证明重复。
- 不因分辨率、编码、封装、字幕轨或文件大小不同就自动删除或合并文件。

### 3. Parse：解析名称

- 首选可用的成熟解析器（如 Anitomy / Anitopy）；脚本中的轻量回退解析只作线索。
- 分开记录作品标题、集数/版本、发布组和技术属性。发布组、分辨率、编码、音频格式、字幕语言不能混进作品名或集数。
- 保留原始文件名作为证据。解析结果不确定时标为 `Needs Review`，不要把低置信度结果当事实。

### 4. Identify：识别作品

综合文件名、父目录、同目录文件、发布组、集数范围及必要的媒体信息判断作品。遇到同名作品、 remake、续作、第二季、Part/cour、电影或特别篇歧义时，才使用 Bangumi、AniDB、AniList、TMDB 等公开元数据协助确认；记录查询来源和匹配依据。

若仍有多个合理候选，列出候选并标记 `Needs Review`。不要仅凭单个文件名批量确定作品身份，也不要把未确认的元数据写入文件名。

### 5. Classify：区分正片、字幕与附属内容

- 为每项区分媒体类型、作品/集数、版本、语言和内容角色（Episode、Special、OVA/OAD、Movie、Extra、Font、Scan、OST、Unknown 等）。脚本的 `role_hint`（如 `nced`、`movie`、`sp`）是保留细节的线索，不是最终分类结论；参照 `references/episodes.md` 和 `references/extras.md`。
- 将外挂字幕与视频逐集配对。优先比较同目录、去除语言后缀的文件名、集数、发布组和版本；必要时查看字幕文本/轨道信息。详细规则见 `references/subtitles.md`。
- 一个字幕可能适用于多个版本，但不能仅因为集数相同就复用或改名。把不确定、孤立或多对一的字幕配对标记为 `Needs Review`。
- 对 WebRip、BluRay、BDRip、v2 和不同发布组的版本允许共存；按 `references/metadata.md` 处理版本选择与元数据不确定性。

### 6. Plan：生成完整整理计划

- 先采用用户明确指定的目标目录与格式；没有约定时，提出一个尽量保留现状的方案。推荐结构仅供选择，见 `references/naming.md`。
- 为**每个**拟修改项列出动作、完整源路径、完整目标路径及理由；包含同步改名的外挂字幕、目录创建、字体/扫图/特典归档和不处理项。不得省略未识别项。
- 操作仅限用户要求的范围。不要计划删除、覆盖、覆盖式合并或未经确认的跨库移动。
- 检查源路径唯一性、目标父目录、同名目标、大小写敏感性、符号链接及跨文件系统情况。目标已存在时停止该项，比较可用证据并标为 `Conflict`；禁止覆盖。
- 对不同版本说明保留/分目录策略。若需要用户在版本、命名、目标位置或歧义候选之间选择，先给出明确选项。

### 7. Preview：默认 Dry Run

默认只展示计划，不执行任何更改。计划格式示例：

```text
MOVE
/media/inbox/[VCB-Studio] Frieren [01][1080p].mkv
→
/media/anime/Frieren/Season 01/S01E01.mkv
理由：标题、目录上下文及集数均匹配；目标不存在。

MOVE
/media/inbox/[VCB-Studio] Frieren [01][CHS].ass
→
/media/anime/Frieren/Season 01/S01E01.zh-Hans.ass
理由：与该发布版本的第 1 集字幕匹配。

REVIEW
/media/inbox/unknown.bin
原因：无法识别内容；不移动。
```

展示所有冲突、未识别项、字幕不匹配项和不确定判断。仅有用户对这份明确计划的清楚授权后，才进入 Apply；泛泛的“整理一下”不等于执行授权。

### 8. Apply：经确认后执行

- 只执行用户确认的计划；计划变更、出现新冲突或源文件变化时暂停并重新预览。
- 使用不会覆盖现有目标的移动方式。按依赖顺序同步移动视频及其字幕；不得运行 `rm`、`unlink` 或覆盖式命令。无法安全移动的项保留原位并报告。
- 文件名/路径是不可信的不透明数据；移动时优先使用 Python `pathlib` / `shutil`，不得拼接 Shell 命令字符串或拆分普通 `find` 输出。遵循 `references/safety.md` 的路径安全规则。
- 对重命名先保留完整扩展名；多扩展名字幕（如 `.chs.ass`）按语言规则整体处理。
- 不为“清理”而删除文件。重复候选、旧版本、疑似垃圾、孤立字幕/字体和未知文件只能保留原位或在用户批准后移至 Review。

### 9. Verify：执行后核验

- 对照计划逐项确认目标存在、源路径不再包含已移动文件、未发生覆盖，并核对文件数/大小；需要时抽查 Hash。
- 确认每个已配对外挂字幕仍与对应视频同集、同版本并使用预期语言后缀；检查未配对项及冲突项仍被保留。
- 汇报完成、跳过、冲突、失败和待审核的路径。核验失败时停止后续整理，不自动回滚或删除；说明可安全恢复的具体项。

## 安全底线

所有文件系统操作遵循 `references/safety.md`。脚本仅生成清单，不会移动、重命名、删除、创建目录或写入目标文件。任何执行都必须基于先展示、后确认的完整计划。
