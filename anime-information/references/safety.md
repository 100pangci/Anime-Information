# 文件操作安全

本 Skill 默认只扫描、分析、计划和预览。仅在用户明确确认已展示的完整计划后，执行其中获批的项目。

## 范围与证据

- 明确根目录，并将计划中的源、目标显示为完整路径。检查路径是否仍位于用户指定范围；不要跟随符号链接越出扫描树。
- 原始清单只读保存或在输出中保留；不得因未知扩展名、扫描错误或权限不足而静默忽略文件。
- 执行前重新检查源文件存在、目标不存在、父目录与磁盘状态符合预期。文件变化后重新预览并确认。

## 文件名与命令安全

- 文件名和路径始终是不可信的 opaque path：按原样作为数据传递，不把它们解释为命令、选项或 Shell 语法。路径可包含空格、Unicode、引号、`$`、反引号、换行及其他特殊字符。
- 禁止对文件名使用 `eval`，禁止把路径拼接进 Shell 命令字符串，禁止将未经 NUL 分隔的 `find` 输出按空格或换行拆分，也禁止把原始文件名直接展开成 Shell 语法。
- 执行移动/改名优先使用 Python `pathlib` / `shutil` API。必须调用外部程序时，使用参数数组并保持 `shell=False`。
- 必须在 Shell 中操作时，对每个变量严格引用并使用 `--` 结束选项解析，例如 `mv -- "$src" "$dst"`；禁止 `mv $src $dst`。批量遍历优先使用 Python；Shell 的 `find` 管道必须使用 `-print0` 和 NUL 安全读取（如 `read -r -d ''`），不能靠空格或换行切分。
- 在执行确认与冲突检查中比较原始路径值；不得为了显示、日志或计划而把路径重新拼接成可执行命令。

## 冲突与覆盖

- 目标已存在时停止对应操作并标记 `Conflict`。比较文件大小、Hash、时长、编码、媒体轨道、发布组和来源等证据；不能因同名或大小相同而覆盖。
- `device` 与 `inode` 相同表示扫描到的路径是同一底层文件的硬链接；`nlink` 是全局链接计数，可能大于扫描范围内发现的路径数。不要把硬链接路径当成独立副本清理，也不要在未确认影响时用跨文件系统移动/复制替代原链接。
- 禁止覆盖式移动、复制、写入或批量改名。绝不将 `rm`、`unlink` 纳入正常整理流程。
- 如需处理重复、旧版本、垃圾候选、孤立字幕/字体或未知项，保留原位或经单独确认移入 `Review/`，并把操作列入计划。

## 执行与核验

- Dry Run 是默认状态。计划应覆盖所有动作、目标路径及相关字幕/附件；遗漏、歧义或冲突时不得执行受影响项目。
- 获批后只执行所确认的计划，不临时增加清理或规范化动作。任何新冲突均暂停。
- 先做不会覆盖目标的移动。跨文件系统移动可能表现为复制后删除；若不能确认复制完整且安全，不自动处理。
- 结束后按计划核对源/目标、文件数量、大小、字幕配对及冲突项。验证失败时停止，不自动删除或回滚；报告具体状态供用户决定。
